# Taste

- Prefers user-facing labels to use common, friendly names rather than internal identifiers: metro lines should display as "Yellow Line"/"Blue Line" (color-based) even when the underlying data only provides numeric names like "Line 2" — map the friendly name at the data/display layer, not just in one component. Confidence: 0.85
- Prefers route/journey displays to be "production-grade" polished: accurate line colors, line-colored arrows/rails that visually signify which line each leg uses, glowing start/end markers, and clean cards — not plain dots and thin arrows. Confidence: 0.9
- Prefers pixel-precise route-timeline geometry: directional arrows must point in the actual travel direction (e.g., down for a downward route), the connector rail must flow continuously into the next station dot with no visible gap, and line-change chips should be centered with symmetric margins and balanced padding. Confidence: 0.85
- Prefers UI feedback delivered as screenshots and expects layout/bug fixes to be visually verified before completion (headless Chrome screenshot; when the image/vision check is inconclusive, verify with DOM dumps and pixel-level scans rather than assuming the fix worked). Confidence: 0.9
- Prefers detail pages (e.g., station pages) to be information-dense: surface the full available facility metadata from the source data — description, amenity flags, gates with accessibility info, lifts/escalators, parking capacities, and contact numbers — rather than keeping the page sparse, and flags a prod page missing those sections vs local as incomplete data. Confidence: 0.85
- Prefers journey results to show platform-level guidance for the whole trip: boarding platform at origin, both arrive and depart platforms at each interchange/change line, and exit platform at the destination. Confidence: 0.85
- Prefers lucide-react icons over emojis for UI iconography, with explicit exceptions preserved as-is (e.g., keep train emoji). Confidence: 0.9
- Prefers space-maximizing header layout: collapse secondary toggles like Favorites/Recents into compact icon buttons beside the status pill (e.g., live network data) to keep maximum space for search, rather than center text toggle rows. Confidence: 0.85
- Prefers network/SVG maps to support full 2D panning (drag/scroll top/bottom/left/right) in addition to zoom, not zoom-only navigation. Confidence: 0.8
- Prefers dense map labels to be zoom-gated: hide station names at overview zoom and reveal them on deep zoom to avoid clutter. Confidence: 0.8
- Prefers map/SVG text labels to stay legible at any zoom: constant screen-readable size that does not shrink when zooming in, large enough to read without strain. Confidence: 0.75
- Prefers interactive map/SVG labels to be non-selectable (user-select: none, pointer-events: none) so text selection never interferes with drag/pan/scroll gestures. Confidence: 0.75
- Prefers planner action controls right-aligned on desktop/tablet with secondary icon actions kept inline in the same row as adjacent controls on mobile and primary button full-width below, rather than left-aligned, centered, or fully stacked. Confidence: 0.8
- Prefers journey planner to offer multiple route optimization preferences (fastest/time, shortest distance, fewest stops, cheapest fare, fewest transfers) with a persisted default, rather than a single fixed route. Confidence: 0.85
- Prefers option pickers to use compact native `<select>` elements inline on the same row as the primary action, rather than multi-row custom chip/radio groups that take a separate row. Confidence: 0.75
- Prefers horizontally scrollable chip/carousel strips to expose explicit side-arrow affordances (YouTube category-scroller style) that scroll on tap and auto-hide at each end, rather than relying on swipe alone with no visible indicator. Confidence: 0.8
